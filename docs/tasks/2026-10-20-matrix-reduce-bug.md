# Баг: Матриця Долі зводить числа до аркану неправильною формулою

## Симптом (живий сайт, 20.10.2026)

Дата 15.03.2002 → 7 з 13 позицій показують XXII (Дурень): зона комфорту, увесь кармічний хвіст
(вхід/урок/вихід) і всі три призначення. Користувачка, яка порахує свою матрицю на іншому сайті
або в таролога, побачить інші аркани і вирішить, що Lunaris рахує неправильно.

## Причина

`backend/TaroSideAI.Domain/Matrix/MatrixCalculator.cs` → `ReduceToArcana` **віднімає 22**, поки число > 22:
44 → 22, 25 → 3, 27 → 5.

У методиці Ладини (яку заявлено в коментарі `DestinyMatrix.cs`) правило інше: **якщо число > 22, складаємо його цифри,
доки не вийде 1..22**: 44 → 8, 25 → 7, 27 → 9, 29 → 11, 46 → 10.
Джерела: https://nfront.org.ua/iak-chytaty-matrytsiu-doli/ (31→4, 36→9, 45→9, 35→8),
https://vikna.tv/dlia-tebe/matrytsya-doli-shho-tse-ta-yak-i-pro-shho-mozhna-diznatysya/ (29→11, 41→5, 46→10).

Чому зараз так багато XXII: при відніманні будь-яке `R(x + 22)` = `x`, а `R(22 + 22)` = 22. Тож щойно D = 22,
центр, хвіст і похідні від них «прилипають» до 22.

## Що зробити

1. `ReduceToArcana`: замінити віднімання на суму цифр у циклі:
   ```csharp
   public static int ReduceToArcana(int number)
   {
       while (number > MaxArcana)
           number = SumDigits(number);
       return number;
   }
   ```
   Оновити коментар над методом (приклади 27 → 9, 25 → 7).
2. Перевірити `R(...)` для вхідних даних нуля: `number` ніколи не має бути 0 (день ≥ 1, місяць ≥ 1, сума цифр року ≥ 1),
   але якщо дійде 0 — кинути `ArgumentOutOfRangeException`, а не повертати 0.
3. `backend/TaroSideAI.Application.Tests/MatrixTests.cs`: існуючі очікування рахувались **неправильною** формулою —
   переписати їх, не підганяти код під старі тести.
   - `ReduceToArcana`: `(22,22) (23,5) (25,7) (27,9) (29,11) (44,8) (45,9) (46,10) (99,18)`.
   - Додати повний референсний тест на 15.03.2002 (пораховано незалежно за правилом суми цифр):
     ```
     A=15 B=3 C=4 D=22 E(центр)=8
     F=18 G=7 H=8 I=10
     KarmicTail = [22, 7, 3]          // D, D2, D1
     LineCenter=15 Money=9 Love=18
     Sky=7 Earth=19 Personal=8
     MaleLine=8 FemaleLine=17 Social=7 Spiritual=15
     ```
   - Перерахувати інші наявні фікстури в тестах (14/5/5/2…, сумісність пари) вручну за новим правилом і оновити.
   - Тест «всі точки в 1..22» лишити.
4. Сумісність пари (`Compatibility`) використовує той самий `R`, окремо нічого не треба, але тест сумісності оновити.
5. `dotnet test` — зелено. Задеплоїти.

## Перевірка після деплою

На `/matrix` дата 15.03.2002 → зона комфорту **VIII**, кармічний хвіст **XXII → VII → III**,
призначення **VIII / VII / XV**.

Кешу/збережених матриць у БД немає? Перевір: якщо прочитання Lunaris (`POST /api/matrix/reading`) зберігається в історії
з уже порахованими арканами — старі записи лишаються як є, нові рахуються правильно; мігрувати не потрібно.
